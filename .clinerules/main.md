# Правила проекта DWH

Документ нормативный. Если код противоречит правилам — исправляй код (или спроси
пользователя), но не подстраивай правила под код и не копируй нарушения как образец.
Один пункт = одно проверяемое требование. Формулировки императивные.

## 1. Контекст

- Назначение: тестовая контейнерная инфраструктура для разработки и проверки DWH
  (PostgreSQL, ClickHouse, dbt; Airflow — опционально).
- Запуск: локально, Docker Compose v2.20+ командой `docker compose` (не `docker-compose`).
- Поддерживаемые ОС: Windows, Linux, macOS. Работа над проектом и развёртывание обязаны
  выполняться на всех трёх ОС без правок в репозитории; ОС-специфичный приём не должен
  оставаться единственным вариантом.
- Оболочки: Windows — PowerShell 7 (`pwsh`); Linux и macOS — POSIX-shell (`bash`, `zsh`).
  Пути в командах — в двойных кавычках (работает во всех трёх оболочках).
- Команды, зависящие от оболочки, приводи в двух вариантах — PowerShell и `bash`/`zsh`.
  Команды, одинаковые на всех ОС (`docker compose ...`), дублируй один раз без привязки
  к ОС.
- Источник истины по параметрам: `.env` (не коммитится) + `.env.example` (коммитится).

## 2. Именование

| Сущность                | Шаблон                            | Пример                                    |
|-------------------------|-----------------------------------|-------------------------------------------|
| Директория контейнера   | `<image>_<tag>`                   | `postgres_18.6-trixie`                    |
| Dockerfile              | `<директория>/Dockerfile`         | `postgres_18.6-trixie/Dockerfile`         |
| Compose-файл контейнера | `docker-compose.<директория>.yml` | `docker-compose.postgres_18.6-trixie.yml` |
| Сервис в compose        | = имя директории                  | `postgres_18.6-trixie`                    |
| Данные контейнера       | `<директория>/data/`              | `postgres_18.6-trixie/data/`              |
| Общие ресурсы           | `volume/<поддиректория>/`         | `volume/init/`                            |

- `container_name` не задавай: обращение к контейнеру — по имени сервиса.
- Тег образа пинни полностью; `latest` запрещён.

## 3. Dockerfile

- Базовый образ — официальный, версия зафиксирована в теге и совпадает с `<tag>` директории.
- Ставь только необходимое; после `apt-get install` очищай `/var/lib/apt/lists/*`.
- В каждый образ устанавливай `mc` (Midnight Commander) — штатный инструмент диагностики
  и просмотра файлов внутри контейнера. Шаблон:

  ```dockerfile
  USER root
  RUN apt-get update \
      && apt-get install -y --no-install-recommends mc \
      && rm -rf /var/lib/apt/lists/*
  USER <штатный пользователь образа>
  ```

- Установку выполняй от `root`, затем возвращай пользователя, который был в базовом образе:
  для ClickHouse — `USER clickhouse`; для Postgres `USER` не задавай — официальный образ
  сам переключается на `postgres` через entrypoint. Без `USER root` установка в образах
  с непривилегированным пользователем упадёт.
- Если в базовом образе нет пакетного менеджера и `mc` установить нельзя — явно
  зафиксируй исключение в README и в коммите, не оставляй это молча.
- Не копируй в образ данные, секреты и `.env`.

## 4. Docker Compose

- Каждый сервис обязан запускаться отдельно:
  `docker compose -f "docker-compose.<директория>.yml" up -d --build`.
- Корневой `docker-compose.yml` собирает все сервисы через `include:` и не дублирует
  их описания. Если `include` недоступен — используй `-f file1 -f file2`, но не копируй
  сервисы между файлами.
- Обязательные ключи сервиса: `build.context` + `build.dockerfile`, `volumes`, `ports`,
  `environment`, `restart: unless-stopped`, `healthcheck` (для БД).
- `depends_on` с `condition: service_healthy` добавляй только для сервисов, которые
  без БД не стартуют (например, dbt).
- Явную секцию `networks` в пер-контейнерных файлах не задавай: один сервис живёт
  в дефолтной сети проекта. Корневой compose через `include:` объединяет сервисы
  в общую сеть проекта (`dwh_default`), внутри неё обращение — по имени сервиса.
- Порт публикуй только тот, что нужен снаружи; внутренние порты не публикуй.

## 5. Порты (host:container)

Хост-порт = `1` + стандартный порт. Меняется только левая часть.

| Сервис              | Контейнер | Хост  |
|---------------------|-----------|-------|
| postgres            | 5432      | 15432 |
| clickhouse (http)   | 8123      | 18123 |
| clickhouse (native) | 9000      | 19000 |
| airflow webserver   | 8080      | 18080 |
| dbt docs serve      | 8080      | 18081 |

- Формат записи только строкой: `- "18123:8123"`.
- Новый порт → сначала добавь его в эту таблицу, затем в compose и README.

## 6. Секреты и .env

- Пароли, пользователи, БД, хосты и порты — только через `.env`. В compose используй
  подстановку без секретных дефолтов: `${POSTGRES_PASSWORD:?POSTGRES_PASSWORD is not set}`.
- Ключи: `<SERVICE>_HOST`, `_PORT`, `_USER`, `_PASSWORD`, `_DB` в верхнем регистре
  (`POSTGRES_*`, `CLICKHOUSE_*`, `DBT_*`, `AIRFLOW_*`).
- Добавил или переименовал переменную — в том же изменении обнови `.env.example`
  (только заглушки, например `change_me`) и README.
- `.env` не коммитится и не цитируется в README. Отсутствие `.env` — ошибка
  пользователя, а не повод прописать пароль в compose.

## 7. Данные и volume

- Состояние контейнера — только в `<директория>/data` (bind-mount, `rw`), например:
  `- ./postgres_18.6-trixie/data:/var/lib/postgresql/data:rw`.
- Каждый новый `data/` покрывается правилом `.gitignore` `*/data/`; отдельные записи
  не нужны.
- Файлы внутри `data/` не редактируй и не читай «наугад»; для запросов используй клиент.
- `volume/` — версионируемые общие ресурсы (init-скрипты, конфиги). Монтируй их `:ro`,
  если контейнер не должен их менять.

## 8. dbt (действует, когда в репозитории появится dbt-проект)

- Профиль подключается через переменные окружения из `.env`; секретов в `profiles.yml` нет.
- Проверка: `dbt debug` из директории dbt-проекта.
- Отчёты: `dbt docs generate`, затем `dbt docs serve` с публикацией на `18081`.
- В `.gitignore` уже учтены `target/`, `logs/`, `dbt_packages/`.

## 9. Документация

README.md обязателен и содержит разделы:

1. Требования (Docker, Compose, версии).
2. Подготовка: создание `.env` из шаблона (`Copy-Item` в PowerShell, `cp` в `bash`/`zsh`)
   и какие значения заполнить.
3. Запуск всего: `docker compose up -d --build`.
4. Запуск отдельного контейнера: команда с `-f`.
5. Остановка: `docker compose down` (без `-v`).
6. Подключение: хост, порт, пользователь, БД (значения — из `.env`, без паролей).
7. Проверка dbt: `dbt debug` (когда появится dbt-проект).
8. Отчёты: URL и порт (`http://localhost:18081`).

- Любое изменение портов, переменных или команд → правка README в том же изменении.
- Команды развёртывания и запуска, которые различаются между ОС (копирование файлов,
  активация окружения, работа с путями), приводи в README в двух вариантах: PowerShell
  (Windows) и `bash`/`zsh` (Linux, macOS).
- Не оставляй в README команды только для одной ОС, если для другой ОС нужен другой
  вариант.
- Язык README и комментариев — русский; имена файлов, сервисов и переменных — латиница.

## 10. Проверка перед сдачей (Definition of Done)

- [ ] `docker compose -f "docker-compose.<директория>.yml" config -q` проходит без ошибок.
- [ ] `docker compose -f "docker-compose.<директория>.yml" up -d --build` поднимает сервис,
      `healthcheck` зелёный.
- [ ] `mc` установлен во всех образах: `docker compose exec <сервис> mc --version`
      выполняется без ошибок.
- [ ] Данные пишутся в `<директория>/data`, путь покрыт `.gitignore`.
- [ ] Все параметры вынесены в `.env`, ключи добавлены в `.env.example`.
- [ ] Порты соответствуют таблице, формат `"HOST:CONTAINER"`.
- [ ] README обновлён.
- [ ] В README есть команды развёртывания и запуска для Windows (PowerShell) и отдельно
      для Linux/macOS (`bash`/`zsh`) там, где команды различаются.
- [ ] В изменении нет `.env`, содержимого `data/` и секретов.

## 11. Запрещено

- Коммитить `.env`, `data/`, пароли и токены в любом виде (включая README и комментарии).
- `docker compose down -v`, удаление `*/data`, `docker system prune` без явного запроса.
- Тег `latest`, `--privileged`, `network_mode: host`.
- Публиковать в хост порты, не указанные в таблице.
- Оставлять в compose неиспользуемые порты и переменные.
- Хранить состояние в named volume, если требуется инспекция файлов (используй `data/`).

## 12. Текущее состояние репозитория

- Инфраструктура: `postgres_18.6-trixie`, `clickhouse_26.9.13.15-jammy`,
  корневой `docker-compose.yml` через `include:`.
- Кроссплатформенность: инфраструктура рассчитана на Windows, Linux и macOS; README
  содержит варианты команд для PowerShell и `bash`/`zsh`.
- dbt-проекта пока нет: раздел 8 и пункт 7 раздела 9 — целевое состояние.
- `.tmp/airflow.compose.yaml` — черновик вне инфраструктуры (`.tmp` в `.gitignore`).
  При переносе Airflow в инфраструктуру: порт `8081:8080` → `18080:8080`,
  named volume → `airflow/data/`, директория — по шаблону `<image>_<tag>`.
